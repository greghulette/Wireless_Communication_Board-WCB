WCB WiFi Setup

Give a board an access point — or join one — so you can manage the mesh from a phone. Connect over USB; this is first-contact setup, so it cannot be done over the network.

1 · Connect

Not connected

2 · Board status

Mesh channel: unknown — WiFi always uses this channel. One radio means the AP and ESP‑NOW share it, so it follows ?WCBCH and cannot be set separately here. A mismatch would be a silent mesh blackout, which is why it is not offered as a choice.

3 · Mode

ESP‑NOW only. USB stays the way in. This is the default.

The password is mandatory. This interface accepts commands for the whole mesh with no credential of its own, so an open AP would hand your droid to anyone in range. The board refuses to start an open one.

That network must be on mesh channel ?. A NaviCore hosts its AP on its own mesh channel, so it matches by construction. If the board lands anywhere else it disconnects on purpose rather than go deaf, and says so. It retries forever and never falls back to hosting its own AP.

4 · Apply

Settings are stored immediately but take effect on the next boot — the same rule ?WCBCH follows. Re-entering the WiFi driver underneath a running mesh would strand the rest of a config push, so the board waits for a clean restart.

Board output

Not connected.

Once WiFi is up, the board is reachable at the address it prints. Note that a page served over HTTPS (including this one) cannot open a plain ws:// or http:// connection to it — browsers block mixed content outright. Use a native app, or serve a tool from http://localhost, to talk to the board over the network.
