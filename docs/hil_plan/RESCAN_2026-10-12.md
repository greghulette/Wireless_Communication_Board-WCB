> Written 2026-10-12 after full run `20261012-020744` (1149/1150), when Greg asked whether every feature of NaviCore, the WCBs
> and Intellex is tested and said "Do it please" to this audit and to building what it finds. NaviCore had the same audit
> on 2026-10-11 (`NAVICORE.md`), and every gap it found is built. Method: six read-only agents, one per slice, each listing every
> user-facing behaviour of its slice from the code and matching it to the test bodies (a test counts only where its assertion
> fails when the behaviour breaks). The brief is `rescan_2026-10-12/BRIEF.md`; each slice has `<slice>.json` (the rows) and
> `<slice>.md` (counts and the gap table). Known-blocked items (`WCB.md` WCB-WP59, `INTELLEX.md` 4.2) were carried over, not re-derived.

## 3. Defects and product questions the scan raised

- **Timer detection is loose** (`wcb-cmd` `timer.loose_semicolon_t_detect`): any `;`-first or plain line containing `;t` anywhere is routed to the timer engine (`command_timer.cpp:73-76`, `WCB.ino:2770`), so unrelated text such as `set;temp` replaces a running timer chain. Probable defect.
- **`?LED,PIN,abc` is accepted as pin 0 and saved** (`wcb-cmd` `led.non_numeric_pin_quirk`, `wcb-store` `led.pin`; `WCB.ino:7182-7183`). Probable defect; noted in s18 before, never sent.
- **The Wizard pushes a non-hex MAC octet** (`wizard` `general.mac_validate`): the hex check runs on blur only, so `?MAC,2,ZZ` can go out; the firmware refuses it since re-scan #5, so the push shows a refusal instead of a silent save.
- **Wizard WLED baud caps disagree** (`wizard` `wled.rows`): `appendWLEDRow` caps S3-S5 at 57600, `onWLEDPortChange` at 9600 (`app.js:3010` vs `:3109`). Decision needed.
- **Intellex finding 20 is still open** (`intellex` `host.api.gh_proxy_ref_unchecked`): a page's `ref` of `..` reaches the cache path.
- **`?Reboot` in mixed case is an unknown command** while the other verbs match in any case (`wcb-store` `reboot.deferred`). Decision needed.
- **The DEBUG help page omits RAW, MGMT and HCR ON/OFF** (`wcb-cmd` `help.debug_page_omits_verbs`). Doc defect in the firmware help.

### Product calls found while building (pinned as today, nothing changed; for Greg)

- **Wizard Connect & Push tip** says "click Use →", but no Use button exists any more (row `wiz.connect_tip_use_button`).
- **Push All with a bad General MAC** aborts every board, one error toast each.
- **WLED baud cap on S3-S5:** a row built there caps at 57600, picking the port caps at 9600; the firmware takes 57600.
- **Kyber Local with S1 and S2 both taken** shows "S1 and S2 both in use", yet a push sends `?KYBER,LOCAL,S2` over the device on S2.
- **Audio Remote host list** offers boards 1 to the quantity only; mapping destinations also offer boards the mesh reported above it.
- **An IF inside a `;t`/`;w` payload** is refused by Test and Save, but a Push sends the row anyway.
- **Load File of a text with no sections** loads an empty system and resets General instead of refusing.
- **Wording:** the HCR tooltips say S3-S5 are limited to 9600 (57600 is allowed); the setup wizard's ETM hints quote 250 ms / 5 s / 3 / 30 s as defaults (they are 500 / 10 / 5 / 2).
- **`?Reboot` in mixed case** is an unknown command while other verbs match in any case.
- **Remote-terminal sessions have no timeout:** a Wizard or Intellex that goes away without `?RTERM,STOP` leaves the board mirroring every console line over the mesh until a reboot. Intellex re-arms once a second; the Wizard does not re-arm, so a timeout would also end an idle Wizard terminal.
- **Intellex:** a failed firmware or docs update answers HTTP 200 `ok: false`, a failed tool update 502; the launcher's Update link shows even when current; the reconnect loop's failure and bounce counters survive a detach and a new attach; a branch named `feature__x` shares a cache folder with `feature/x`; the wiki fetch strips a leading `../` from asset paths; a test host may attach to any WiFi host (no allow-list like the serial one).

- **Setup wizard slot-ID range:** the identity step's hint says 1-8, its check accepts 1-99, the firmware's MAX_WCB_COUNT is 20.
- **HCR Status on a relayed board:** the button is enabled, but the modal then says relay is not supported yet.

### Decisions taken 2026-10-13 (Greg: "use your recommendation" on every point)

- **Applied:** WCB - legacy verbs in any case, `;S<letter>` refused, remote-terminal sessions end 30 s after the last re-arm (WCB `3b9e2dd`, `baa8593` keeps a half-mirrored line on a same-relay re-arm). Wizard - all ten product calls and a 12 s remote-terminal keep-alive (`e19de3d`, `57d9892`, `cdedad7`). Intellex - all eight (`bfaebf4`..`cf5aacc`; failed updates answer 200 `{ok:false}` on all three routes, the WiFi allow-list is `INTELLEX_WS_ALLOW`). NaviCore - a console line goes to USB whole or is dropped whole (`d3ac1da`, bench image navicore-fix11).
- **Tried and reverted:** a 5 s grace window before W1 closes a failing WebSocket client (`3b9e2dd`, reverted in `35046f4`): the loop stalled 9.4 s instead of 3.5 s and the client was dropped anyway. A send path that never blocks the loop is needed; back to Greg (row `ws.burst_closes_live_client`). **Built 2026-10-14** (Greg: "Do it"): WCB `4fd7698` sends with `MSG_DONTWAIT`, keeps a slow client and reports what it drops, closes one that takes no output for 10 s, and answers PING/CLOSE itself; tested by `ws.burst_keeps_live_client`, `ws.stalled_client_costs_nothing` and `ws.ping_pong_and_close`. The same tests found `?BAUD` on S3-S5 abort()ing the board when the heap had no 3.9 KB block (tracker #114, fixed in the same commit).
- **In progress:** test-only fault knobs (`?DEBUG,FAULT,...`), new probe commands (a WDP Maestro advert, a raw frame injector) and the #112 stress test, for the rows that only a fault can reach.

## 4. Build order

1. High risk first, then medium, then low; within a tier unattended before opt-in before attended; blocked rows wait for their knob or hardware.
2. Browser work (the Wizard's 114 and Intellex's no-board rows) needs no bench and runs between bench batches; bench rows run in the GUI (`gui.py --run <ids>`), each verified alone, then in the next full run.
3. A `(should)` test pins each defect above until its fix lands; WCB fixes go to `WIFI` and are flashed to W1-W3 (no release: Greg tests first); Intellex fixes to its `main`.
4. Progress: each row's `status` in the slice `.json` moves to `tested` with its new id in `tested_by`; the revision log in `HIL_TESTING.md` records each batch.
