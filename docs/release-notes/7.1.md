# WCB 7.1

The first release since 7.0.1. The whole mesh now keeps to one radio channel — and follows a WiFi network across channels — the Config Tool gains a Sequence Builder, and a management relay carries configs, results and pushes of any size. Plus a round of reliability fixes, among them a board that clears a wedged ESP-NOW transmit by itself. The first published build of the line is **7.1.1**.

## Upgrading from 7.0.1

- **Your settings and stored sequences come through.** Update the usual way — the Config Tool's **Update FW**, Intellex, or [OTA](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/OTA-Updates) through a relay. The partition layout is unchanged (`min_spiffs`).
- **A board in WiFi JOIN mode needs an access token.** It keeps WiFi off until it has one, and says so at every boot. Set one and reboot: `?WIFI,TOKEN,<token>`, then `?REBOOT`. ESP-NOW keeps working meanwhile, so the board stays reachable through the mesh. See [WiFi → The Access Token](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/WiFi#the-access-token).
- **Channel sync is on by default.** Once your boards are on 7.1, a board joined to a WiFi network on another channel moves the whole mesh to it. Turn it off on every board with `?CHSYNC,OFF` (or **Channel Sync** in the Config Tool) if you'd rather it didn't.
- **Update every board, and NaviCore.** A board on older firmware doesn't follow a channel move and is left behind; the [WDP Mesh](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Config-Tool#wdp-mesh) panel tags each one *older firmware: won't follow a channel move*. Results and pushes of any size through a relay need the board and the relay current too.
- **An OTA refused for size** means the board still has the old 1.25 MB partition layout from a USB flash before 6.1.0. The Config Tool says so now; one **Update FW** over USB fixes it. See [OTA Updates](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/OTA-Updates#the-old-partition-layout--begin-rejected-for-size).
- **Use the current Config Tool, and Intellex 0.2.6.** Intellex users: update Intellex itself (**Update Intellex**), then press **Update tools**. Intellex 0.2.6 signs in with a board's access token.

## New Features

- **Channel sync** — the whole mesh on one radio channel. The board that leads moves everyone with it, and a leader that misses a board it knows searches the other channels and brings it home. `?CHSYNC,MOVE,<ch>` on one board moves the whole running mesh, no reboot for a board without WiFi. On by default; needs ETM and WDP. See **[Channel Sync](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Channel-Sync)**.
  - **JOIN follows its network.** A board joined to a WiFi network that's on another channel moves the mesh there, and finds the network again when the router changes channel.
  - **`?REGION,<cc>`** — the WiFi region, which decides whether channels 12–13 exist. `01`, world-safe channels 1–11, is the default.
  - **In the Config Tool:** Mesh Channel, Region and Channel Sync in General Settings (Advanced), and a **Channel** column in the WDP Mesh panel showing who leads.
- **The WiFi access token** — the WiFi console's login. `?WIFI,TOKEN,<token>` sets it; a client signs in with `?AUTH,<token>`, and Intellex asks for it once. **JOIN mode requires one.** It's on the Config Tool's board card too. See **[WiFi](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/WiFi#the-access-token)**.
- **Sequence Builder in the Config Tool** — lay a stored sequence out on a timeline: drag commands from the DroidNet command library (the one NaviCore's tool uses, with the WCB's own commands added), place them to the millisecond, line them up against other sequences, preview the timing and apply. It writes the `;T` delays and warns about anything the board wouldn't run as drawn. Each sequence row also shows a timing strip. See **[Sequence Builder](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Sequence-Builder)**.
- **Configs of any size through a relay** — a config pull goes in up to 64 parts, about 184,000 characters, more than any board's config can reach: whatever a board can store comes through. Over 16 parts needs the board on 7.1. See **[Management Relay](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Management-Relay#large-configs-come-in-parts)**.
- **Stats, network tests and sequence lists of any size through a relay** — `?MGMT,STATS`, `?MGMT,ETM,CHAR`, the sequence-names list (`?MGMT,SEQ`) and one long sequence (`?MGMT,SEQGET`) come in parts and arrive whole, when the board and the relay are both current (a WCB on 7.1, or WCB_Client 1.20.0). An older requester still gets `[ERROR] Result too large to relay` for a result it can't take in parts. See **[Management Relay](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Management-Relay#stats-and-network-tests-of-any-size)**.
- **Pushes of any size through a relay** — the Config Tool sends a long push as several sessions, the network and restart commands last; one long sequence goes as one long session to a board and relay on 7.1. The Config Tool used to refuse a relay push over 2,864 characters. See **[Management Relay](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Management-Relay#pushes-of-any-size)**.
- **WDP capability tags** — every WCB advertises what its firmware takes (`mgmt.rx24`: a 24-chunk push session), shown as `Tags` in `?WDP,<n>` and read by the Config Tool. See **[WDP](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/WDP-Discovery#capability-tags)**.
- **Test-only switches** `?DEBUG,RESULTPART` and `?DEBUG,ONEREPLY`, for testing results in parts and how older relays ask. Not for use on a droid.

## Changed

- **A relay OTA takes about 3 minutes a board**, down from about 4½ with the relay on USB and about 10 over WiFi through Intellex. The Config Tool keeps several packets in flight, so it works with the firmware already on your boards.
- **Changing a board's number through a relay** goes in two steps when the push is longer than one relay session: the new number and a restart first, then the rest once the relay hears the board under its new number (up to 45 seconds). The board then shows once, under its new number. See **[Management Relay](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Management-Relay#changing-a-boards-number)**.
- **A sequence saved through a relay is checked.** **SAVE/UPDATE** on a sequence row asks the board what it now holds and, through a WCB relay, sends the save again if it didn't arrive — up to three tries — then says whether it stored. Through NaviCore or a MgmtRelay it is sent once and the Config Tool asks you to pull the board to confirm. See **[Config Tool](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Config-Tool#stored-sequences)**.
- **Pushing a number another board already has asks first** — over USB or through a relay, with **Cancel** the default. Two boards on one number share one radio address. See **[Config Tool](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Config-Tool#changing-a-boards-number)**.
- **An OTA refused for size says why**: the old partition layout, and the one USB **Update FW** that fixes it.
- **A USB flash asks for a RESET tap** when the flasher can't put the board into bootloader mode by itself in two tries. A WCB 2.4 has no BOOT button, and some computers and hubs are too slow for the automatic reset.
- **ETM characterization takes its 3.6 KB of memory only while it runs**, so every board has that much more free the rest of the time. A run with no 3.6 KB block free is refused and says why.
- **The WDP Mesh, RC Controllers and Management Relays panels follow the Config Tool's light theme.**

## Bug Fixes

- **A wedged ESP-NOW transmit clears itself.** A board whose radio takes frames and never sends them restarts ESP-NOW, then — with WiFi off — its WiFi driver, and as a last resort restarts itself, at most twice in a row. It used to stay off the mesh until it was rebooted. `?STATS` counts the wedges. See **[Debug Mode](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Debug-Mode#mesh--esp-now-transmit-problems)**.
- **A 3,999-character stored sequence saves on a classic ESP32 too**, even one hosting its access point. A classic board could run out of memory saving more than about 2,400 characters; the save now goes straight from the command line into the store. See **[Stored Commands](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Stored-Commands#storage-architecture)**.
- **The Config Tool loads a full sequence store**, over USB and through a relay, however many sequences it holds. A USB pull of a big store was cut off part-way, a relay pull of one could run out of time, and nearly 3,000 sequences took about 15 seconds to fill the table — now well under a second.
- **A board gives back the memory a relayed request or an OTA used.** It no longer keeps up to about 8 KB tied up until its next reboot after a relayed `?STATS` or network test, or after an OTA — even an aborted one, or a stray OTA packet.
- **A `?BACKUP` of a full sequence store no longer trips the loop watch**, whose `[HANG]` line landed inside the backup's chain and broke its checksum.
- **`?SEQ,NAMES` reads the store when asked**, instead of answering "try again" for 5 seconds after a background read failed.
- **Changing a board's number through a relay works.** The push was addressed to the new number, which the board doesn't answer to until the push has run, so it never arrived.
- **A relay push** with an accented or other non-ASCII character, or cut just after a space, arrives intact, and a command the board can't reassemble whole, short of memory, is dropped instead of run with a piece missing.
- **`?WIFI,JOIN` on a board hosting an access point waits for the reboot**, as it says. It started joining at once, underneath the running access point.
- **The WiFi console echoes a client's close** with its status code and closes cleanly, so a Windows client no longer sees a dropped connection.
- **Config Tool:** a port label's device list no longer closes while you type when something else on the page scrolls.

## Known Issues

- **A computer joining a WCB's access point can wait up to 47 seconds for an address.** The cause is still being looked for.
- **A WCB going silent mid-run** was seen on the bench in long test runs and couldn't be reproduced on demand. The loop watch will show where it stopped if it happens again.

## Compatibility

- **NaviCore:** works with the current NaviCore firmware, built with WCB_Client 1.20.0 and WcbCmd 0.9.2. An older NaviCore doesn't follow a channel move, and one built with WCB_Client 1.18.1 or earlier shows no sequences for a board whose list is too long for one reply (from about 180 sequences).
- **MgmtRelay:** rebuild it with WCB_Client 1.20.0 for channel sync and for stats and network tests of any size.
- **Your own WCB_Client devices:** 1.19.0 or later takes part in channel sync — see [Third-Party Integration](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Third-Party-Integration#channel-sync--following-the-mesh).
- **Config Tool and Intellex:** use the current Config Tool. Intellex users: Intellex 0.2.6 (the access token), then **Update tools**; the Sequence Builder needs Intellex 0.2.2 or later.

The full documentation is the [WCB wiki](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki), whose [Changelog](https://github.com/greghulette/Wireless_Communication_Board-WCB/wiki/Changelog) carries these notes.
